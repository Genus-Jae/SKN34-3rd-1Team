# 지원사업 직접 조건 검색

## 목적과 호출 흐름

자연어 검색과 별도로, 사용자가 선택한 필터를 그대로 적용해 저장된 공고 목록을 조회합니다.
LLM 검색 장애를 숨기는 fallback이 아니라 사용자가 선택하는 별도 조회 기능입니다.

`HTTP GET → SupportProgramCatalogController → SupportProgramCatalogService → SupportProgramRepository → MyBatis Mapper → MySQL`

- 기존 `findPublishedPresent()`로 공개된 스냅샷만 한 번 읽습니다.
- AI Service, OpenAI, Qdrant, 기업마당 외부 API를 호출하지 않습니다.
- 공개 이후 색인 장애가 있어도 목록 조회는 가능합니다. 아직 공개되지 않은 공고는 노출하지 않습니다.
- 기존 AI 요청 제한과 별개로 동작하며, 요청마다 유료 API 비용이 발생하지 않습니다.
- Repository·Mapper·스키마·동기화 정책은 변경하지 않습니다.

## 요청

`GET /api/v1/support-programs/catalog`

| 파라미터 | 기본값 | 허용 범위·동작 |
|---|---|---|
| `keyword` | 빈 문자열 | 최대 100 UTF-16 코드 단위. 앞뒤 공백 제거 후 공고명 또는 기관명에 대소문자 구분 없는 포함 검색 |
| `region` | 빈 문자열 | 최대 50 UTF-16 코드 단위. 앞뒤 공백 제거 후 제공처 지역 태그와 정확히 일치 |
| `category` | 빈 문자열 | 최대 100 UTF-16 코드 단위. 앞뒤 공백 제거 후 제공처 분야 태그와 정확히 일치 |
| `status` | `OPEN` | `ALL`, `OPEN`, `UPCOMING`, `CLOSED`, `UNKNOWN` |
| `sort` | `RECENT` | `RECENT`, `DEADLINE` |
| `page` | `1` | 1부터 1,000,000까지 정수 |
| `pageSize` | `12` | 1부터 50까지 정수 |

- 문자열 길이는 trim 전 입력 기준이며 제어 문자·제로폭 문자 등 Unicode C 범주 문자를 허용하지 않습니다.
- 비어 있거나 공백뿐인 키워드·지역·분야는 해당 필터를 적용하지 않습니다.
- 키워드는 문장 해석·유의어 확장·공백별 토큰 분해를 하지 않습니다. `%`, `_`도 문자 그대로 찾습니다.
- 키워드의 공고명/기관명 조건끼리는 OR이고, 키워드·지역·분야·접수 상태 필터끼리는 AND입니다.
- 알 수 없는 지역·분야 태그는 필터를 무시하지 않고 0건을 반환합니다.
- `status=ALL`은 접수 중·예정·마감·미확인을 모두 포함합니다. 다른 값은 해당 상태만 반환합니다.
- 접수 상태는 기존 Repository에서 서울 기준 현재 날짜와 신청 기간으로 계산한 값을 사용합니다.
- 잘못된 enum, 숫자 형식·범위, 문자열 길이·문자는 DB 조회 전에 `400 REQUEST_VALIDATION_FAILED`로 거부합니다.
  응답에 입력 원문이나 내부 변환 예외를 노출하지 않습니다.

예시:

```http
GET /api/v1/support-programs/catalog?keyword=수출&region=서울&category=수출&status=OPEN&sort=DEADLINE&page=1&pageSize=12
```

## 지역 태그와 자격 판정의 구분

이 기능은 **제공처의 분류 태그**를 탐색 조건으로 사용합니다. 서울은 서울 태그에만 일치하며 경북이나 전국 태그를
자동으로 포함하지 않습니다. 전국 공고는 전국 태그를 직접 선택하거나 지역 필터를 해제해서 찾습니다.

태그에 해당 지역이 있다고 기업 소재지·업종·업력 등 신청 자격이 충족되는 것은 아닙니다. 현재 소재지를 추정하거나
원문 자격 조건을 AI로 판단하지 않으므로, 상세 안내와 공식 원문에서 최종 신청 요건을 확인해야 합니다.

## 정렬과 페이지

- `RECENT`: 제공처 정렬 시각 내림차순. 누락·빈 시각은 마지막. 동점은 `sourceCode`, 원본 `id` 오름차순.
- `DEADLINE`: 신청 종료일 오름차순. 종료일 없는 공고는 마지막. 동점은 위 최신순 정렬 사용.
- `ALL`에서 마감순을 선택하면 이미 마감된 날짜도 포함하여 날짜 오름차순으로 정렬합니다.
- 서로 다른 제공처의 같은 원본 ID는 다른 공고로 보존합니다.
- `total`은 모든 필터 적용 후 건수이고 `totalPages`는 페이지 크기로 나눈 올림 값입니다. 0건이면 0페이지입니다.
- 범위를 벗어난 `page`는 요청 값을 유지하고 `programs: []`와 실제 총건수·총페이지를 반환합니다. 마지막 페이지로
  조용히 이동하지 않습니다.

## 응답

| 필드 | 설명 |
|---|---|
| `programs` | 해당 페이지의 기존 `SupportProgramResponse` 배열 |
| `total` | 필터에 맞는 전체 건수 |
| `page` | 요청한 1부터 시작하는 페이지 번호 |
| `pageSize` | 요청한 페이지 크기 |
| `totalPages` | 필터 결과의 총페이지 수 |
| `regions` | 같은 전체 공개 스냅샷에 존재하는 지역 태그. 빈 값 제외·중복 제거·오름차순 |
| `categories` | 같은 전체 공개 스냅샷에 존재하는 분야 태그. 빈 값 제외·중복 제거·오름차순 |

선택지는 페이지나 현재 필터 결과만으로 줄이지 않습니다. 한 번 읽은 같은 스냅샷으로 목록과 선택지를 계산하므로
요청 도중 동기화되어도 두 조회의 세대가 어긋나지 않습니다.

각 공고는 AI를 통과하지 않았으므로 `matchedReasons: []`, `recommendationScore: null`, `eligibilityReview: null`입니다.
API/DB 장애를 정상 0건 응답으로 바꾸지 않습니다.

## 현재 구현의 범위

현재 저장된 규모에 맞춰 공개 스냅샷을 메모리에서 필터링·정렬한 뒤 페이지를 잘라 반환합니다. 새로운 SQL, 캐시,
인덱스나 외부 의존성은 추가하지 않았습니다. 전체 공고 수·트래픽이 늘면 실제 성능 측정 후 DB 필터·페이지 조회와
선택지 조회를 도입할 수 있으며, 그때 MySQL 8.4 통합 테스트로 동일 계약을 검증해야 합니다.

## 검증 범위

- Service: 기본 접수 상태, 문자 그대로 검색, 지역·분야 정확한 일치, AND 결합, 전체 상태, 전체 스냅샷 선택지,
  최신·마감순, 날짜 누락, 제공처 복합 식별자, 페이지 경계, 자격/추천 필드 제거, DB 실패 전파.
- Controller: 기본값, 필터 전달, 상태/정렬 enum, 숫자·길이·제어 문자 검증, 최대 허용 경계, 기존 공고 응답 호환.
- 변경된 Core 코드의 마무리 검증은 JDK 21의 `./gradlew clean test --no-daemon`으로 실행합니다.
- 단위·통합 테스트 결과를 실제 자연어 검색·추천 품질 측정으로 표현하지 않습니다.
